# JUnit Diff Lens

2回分のJUnit XMLから、新しい失敗・修復・消えたテスト・実行時間の変化を比較します。

**[アプリを開く](https://tomdachs.github.io/junit-diff-lens/)** → 右上の「日本語」→「サンプルで試す」、または基準・現在のXMLを選択してください。

## 利用場面

依存ライブラリ更新の前後、mainと作業ブランチ、前日と今日のCI結果を比較したいときに使えます。アカウントやCI設定変更は不要です。「新しい失敗」から調査し、「詳細」で失敗メッセージを確認します。

ファイルはブラウザのメモリ内だけで処理します。アップロード、アクセス解析、レポートの永続保存はありません。「レポートを消去」または再読み込みで破棄します。サイト本体の配信にはGitHub Pagesへの接続があります。

## 正しく読むためのルール

- suiteの階層・クラス名・テスト名が完全一致するテストを対応付けます。重複があればエラーにし、名前が変われば追加・削除として扱います。
- 失敗から成功だけを「修復」とします。スキップや削除は修復に含みません。
- 新規追加の失敗テストは「追加」に含まれます。状態欄でも失敗を確認できます。
- 「遅くなったテスト」は両方成功で、0.1秒以上かつ20%以上の増加です。単発の実行差から性能劣化を断定しないでください。
- リトライ・flaky拡張、suite単位の失敗は注意を表示します。2回分の結果からflaky判定はしません。
- ファイルは各5 MiB・20,000テストまで、UTF-8のみです。XML形式は[英語版の仕様](../README.md#comparison-contract-and-limits)を参照してください。

出力は絞り込みによらず全件です。JSONとMarkdownにはテスト名・クラス名・suite名・ファイル名が含まれ、失敗本文・ログは含まれません。匿名化機能ではないため、共有前に確認してください。

## ローカルで利用する

[Release](https://github.com/Tomdachs/junit-diff-lens/releases)のZIPを展開し、そのディレクトリで次を実行します。

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

`http://127.0.0.1:8080`を開きます。Windowsでは`python3`の代わりに`py`を利用できます。ZIPには実行用ファイルが含まれ、Node.jsやインターネット接続は不要です。

## 不具合・改善提案

[Issues](https://github.com/Tomdachs/junit-diff-lens/issues)へ、利用ブラウザ、期待した結果、実際の結果をお知らせください。社内パス・トークン・個人情報を除いた最小の架空XMLがあると再現しやすくなります。秘密情報を含む原本は投稿しないでください。
